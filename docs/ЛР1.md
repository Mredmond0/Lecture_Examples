## Часть 1. Чужой код
Я выбрала паттерн **Strategy** из папки `DesignPatterns/Implementation/Behavioral/Strategy`. 
Этот паттерн позволяет выбирать алгоритм (стратегию) во время выполнения программы, не меняя основной класс. В коде есть интерфейс `IStrategy` и классы-реализации. Контекст хранит ссылку на интерфейс и делегирует ему работу.

## Часть 2. Нарушения SOLID в God-классе `LogProcessingModule`

| Принцип | Где нарушен (строка/метод) | Почему это нарушение |
| :--- | :--- | :--- |
| **SRP** | Метод `Run()` | Один метод делает всё: читает конфиг, открывает соединения, читает файл, парсит, фильтрует и пишет. |
| **SRP** | Метод `Write()` | Смешана логика форматирования и вывода (знает про цвета консоли и про SQL). |
| **OCP** | `switch (_config["sink"])` (3 раза) | Чтобы добавить новый приёмник, нужно изменить 3 разных метода в этом классе. |
| **OCP** | `switch (_config["format"])` | Новый формат логов требует правки метода `Format`. |
| **LSP** | Интерфейс `ILogSink` | «Универсальный» интерфейс, который заставляет консоль реализовывать транзакции БД. |
| **ISP** | Интерфейс `ILogSink` | Интерфейс «жирный», реализации вынуждены писать пустые методы. |
| **DIP** | Поля `_configPath`, `_fileWriter` | Класс сам создаёт зависимости (читает файл с диска), их нельзя подменить в тестах. |

## Часть 3. Диаграммы
### 3.1. Диаграмма до рефакторинга (God Object)
```plantuml
@startuml
class LogProcessingModule {
  - _config : Dictionary
  - _connection : FakeDbConnection
  - _fileWriter : StreamWriter
  + Run(logPath: string)
  - LoadConfig()
  - OpenSinks()
  - ParseLine(line: string)
  - Format(record: LogRecord)
  - Write(record: LogRecord)
  - SeverityToInt(severity: string)
}
@enduml
